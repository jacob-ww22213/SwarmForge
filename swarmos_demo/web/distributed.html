分布式小模型接入与任务控制台

这个页面负责两件事：帮助测试用户下载并启动本地小模型节点，以及让控制器统一展示在线节点、路由过程和任务结果。控制器负责调度，不应该要求服务器自己长期承载业务小模型。

1. 选择并下载模型 点击推荐模型卡片，进入官方模型页或直接复制 `ollama pull` 命令。
2. 启动本地节点 在自己的机器上启动 Ollama 与 skill / worker，让节点持续 heartbeat 到 controller。
3. 提交任务 在这里输入任务，由 controller 做 MoE 路由和两轮 MoA 协作。
4. 检查协作结果 查看 MoE 路由、两轮 MoA 结果、耗时、评分与历史记录。
当前系统逻辑 controller 负责调度和展示；用户自己的设备负责运行小模型并接入成在线节点。只有 Ollama 和 worker 都在运行时，这个节点才真正可用。
快速演示 先确认 controller 在线，再让测试用户下载模型并启动自己的节点。节点上线后，直接在这里发任务检查输出。

用户节点接入

这里是给测试用户的下载和接入说明。推荐模型点一下就能打开官方模型页；然后在自己的机器上执行 `ollama pull`，再用 skill 或命令启动节点即可。

步骤 A 先在自己的电脑安装 Ollama，然后运行 `ollama serve`。如果这一台机器还没有下载过本项目，后面优先使用 bootstrap 命令，不要先直接调用 repo 内 skill。
步骤 B 在下面选一个推荐模型，打开官方页面或复制 `ollama pull` 命令下载。推荐先用 `qwen2.5:0.5b` 做首次接入测试。
步骤 C 第一次接入新电脑：先运行 bootstrap 脚本自动 clone 仓库、创建环境并启动 worker。只有仓库已经在本地，才适合再使用 `swarmforge-demo-runner` 这个 repo 内 skill。
步骤 D 保持 Ollama 和 worker 不退出。回到页面后，如果在线节点数量仍是 0，优先检查 `CONTROLLER_URL` 和 `NODE_PUBLIC_IP` 是否填成了真实地址，而不是 `127.0.0.1`。

步骤 1. 填写接入参数 先填 controller 地址和这台用户电脑自己的可访问 IP。向导会自动生成 bootstrap 和 skill 命令。
步骤 2. 先看地址规则 这两个地址最容易填错，特别是跨机器接入时。
先理解两个地址： - CONTROLLER_URL：当前页面所在服务器公网入口，例如 http://31.97.191.47/ - NODE_PUBLIC_IP：这台用户电脑能被 controller 访问到的 IP 不要把远程 controller 写成 127.0.0.1。 在用户电脑上，127.0.0.1 只代表“这台用户自己的电脑”。
步骤 3. 复制命令并执行 第一次接入新电脑优先用 bootstrap。只有仓库已经在本地，才再用 repo 内 skill / 脚本。
