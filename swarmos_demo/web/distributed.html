SwarmForge Distributed Console

项目方与用户共用的多机小模型控制台

这个页面同时服务两个角色。项目方可以发布任务、检查系统状态和聚合结果；用户可以下载小模型、启动本地节点、保持在线，并从自己的视角发任务和检查结果。

1. 用户上线节点 启动 Ollama 与 worker，持续 heartbeat 到 controller。
2. 下载小模型 在页面里输入模型名，直接下载或切换到当前节点。
3. 双角色发任务 项目方和用户都可以在页面提交任务并查看执行结果。
4. 检查协作结果 查看 MoE 路由、两轮 MoA 结果、耗时、评分与历史记录。
当前系统逻辑 controller 负责调度和展示，worker 负责把本地模型接入成在线节点。只有 Ollama 和 worker 都在运行时，这个节点才真正可用。
快速演示 先启动 controller，再启动 2 个 mock 或 Ollama worker。然后切换到不同角色页签，分别发任务检查输出。

角色入口

你可以切换项目方视角和用户视角。两个角色都能提交任务和查看结果。

项目方视角 适合做平台任务发布、系统状态检查、节点利用率观察和结果验收。

任务发起

当前选中角色会作为任务来源写入历史记录。任务提交后，controller 会执行 MoE 路由和两轮 MoA 协作。

用户节点接入

这是面向用户的“小模型下载与保持在线”入口说明。下载模型不等于节点在线，必须同时运行 Ollama 和 worker。

步骤 A 先在节点机器上启动 `ollama serve`，让本地模型服务保持可访问。
步骤 B 再启动 `swarmos_demo.worker`，把这台机器注册成在线节点。
步骤 C 在右侧节点卡片里输入模型名并点击“下载模型”或“切换模型”。
步骤 D 保持 Ollama 和 worker 不退出，页面状态持续显示 `ONLINE`。
使用 swarmforge-demo-runner 下载并启动本地小模型节点
ollama serve ollama pull qwen2.5:7b python3 -m swarmos_demo.worker \ --controller-url http://127.0.0.1:8010 \ --public-url http://127.0.0.1:8021 \ --host 127.0.0.1 \ --port 8021 \ --provider ollama \ --base-url http://127.0.0.1:11434/v1 \ --model qwen2.5:7b \ --worker-id worker-a \ --name Worker-A \ --role-key coding_worker \ --role-name "Coding Worker"
